# Адаптивный PDF → Markdown через Ollama

## Цель и согласованные требования

Любые PDF с русским текстом и формулами: цифровые документы, сканы, повреждённый текстовый слой и смешанные страницы. Результат — Markdown с HTML-таблицами; формулы отображаются в LaTeX, настоящие рисунки остаются PNG-ресурсами. Части одной таблицы на разных страницах обрабатываются как одна логическая таблица. Локальная Gemma не устанавливается: распознавание выполняет Ollama Cloud. Папки `PDF` и `Output` рядом с программой сохраняются.

Один запускатель должен работать на macOS, Ubuntu 25 и Windows 10/11. Установка из EyesHead/marker выполняется один раз; дальнейшие обновления запускаются явно или при необходимом переходе со старого конвейера. Ключ хранится только в памяти процесса.

## Что исправляется в текущем коде

- LaTeX сейчас записывается в `img.alt`, а изображение формулы остаётся видимым содержимым. Новый результат содержит настоящие `<math>`/Markdown-формулы.
- Сейчас все подходящие растровые объекты таблицы отправляются в одном запросе. Фрагменты операторов и переменных распознаются по отдельности, без целого выражения.
- LLM обрабатывает фрагменты таблиц до их склейки. Нужно сначала определить логическую таблицу и сохранить исходные координаты каждого её фрагмента.
- Проверка ответа LLM возвращает пустой результат при ошибке схемы и не исправляет ответ. Запускатель при этом не учитывает неполное распознавание.
- Накопительная статистика показывается рядом с числом таблиц текущей порции страниц, что даёт противоречивые счётчики.
- Запускатель использует Bash, POSIX-пути и AppleScript; прямой запуск на Windows не предусмотрен.

## Единицы обработки и ограничение контекста

1. Сначала извлечь текст, границы и изображения PDF, сохраняя исходные координаты и номера страниц.
2. Определить качество текста для каждой страницы/области. Надёжный текст и векторную сетку использовать напрямую. Плохие или отсутствующие данные дополнить распознаванием PNG-области через Ollama.
3. Найти и связать продолжения таблиц. Не склеивать разные таблицы лишь по близкому числу колонок; учитывать границы, заголовки, подписи и решение LLM при неоднозначности.
4. Формулы обрабатывать целыми выражениями с ближайшим контекстом: объединять принадлежащие одной строке фрагменты изображения и текста. Вне таблиц применять тот же путь к блочным и встроенным формулам. Не ограничивать кандидатов только уже размеченными `Equation`.
5. Для таблицы передавать PNG-фрагменты, текст/координаты и уже надёжную сетку. Небольшую таблицу обрабатывать за один запрос; большую — окнами строк/ячеек с повторённой шапкой и перекрытием. Полученные части код объединяет в один HTML.
6. Каждый запрос ограничивать заданным бюджетом текста, изображений и ответа. Переполнение контекста приводит к уменьшению окна, а не к отправке всего документа заново.

Исходные координаты страниц остаются неизменными. Координаты виртуальной склейки используются только для отображения, а не для повторного вырезания из PDF.

## Формулы и рисунки

PNG формулы сохраняется для проверки; в итоговом содержимом стоит LaTeX. Для смешанной ячейки модель возвращает текст с `<math>`, а код сохраняет её положение и объединения. Кропы с рисунками классифицируются отдельно и остаются `<img src="…png">` в исходной ячейке. Не подменять рисунки текстовыми описаниями.

Растровые картинки извлекаются в исходном разрешении, если это возможно. Для векторного содержимого применяется настраиваемое высокое DPI; увеличение маленького исходного растра не считается улучшением качества. Распознающий запрос может использовать уменьшенную копию, сохраняя полный ресурс.

Нечитаемые формулы не выдумываются: остаётся исходный PNG с явным статусом неполного распознавания. Ни один алгоритм не гарантирует восстановление информации, отсутствующей в исходнике.

## Ответы LLM и автоматические проверки

Небольшие контракты отдельно для формулы, содержимого ячейки, структуры таблицы и OCR-области. Проверяются синтаксис, наличие обязательного содержимого, допустимые ссылки, парность математических разделителей и границы объединений. Надёжную сетку LLM не может изменить без отдельной проверки.

При невалидном ответе выполняется ограниченная попытка исправления с конкретными ошибками. Повторные запросы используют соответствующий кроп, а не весь PDF. Для Cloud учитывается отсутствие гарантированного принудительного JSON Schema. В журнал выводятся тип и место ошибки без ключа и base64 изображений.

Результат с нераспознанными обязательными областями сохраняется для просмотра, но не объявляется полностью успешным. Отдельный JSON таблиц не возвращается; служебная сводка распознавания относится к метаданным конвертации.

## Запуск на трёх ОС

Общее управление установкой и запуском — в Python с `pathlib`, `venv` и `subprocess` без shell-интерполяции. Тонкие обёртки для Bash и PowerShell/Windows передают параметры общему запускателю. macOS сохраняет существующий `ScriptMacOS-Ollama.sh` как совместимый вход.

Диалог ключа: системное окно macOS, защищённый ввод Windows/доступный GUI, защищённый терминальный ввод как переносимый запасной вариант. Поддерживается `OLLAMA_API_KEY` из окружения.

Адаптивный облачный OCR не должен зависеть от запуска тяжёлого локального VLM-сервера, который не одинаково доступен на разных ОС. Существующий Marker CLI сохраняется; облачный адаптивный путь выбирается явно общим запускателем.

## Проверка результата

- Регрессии по приложенным символам и таблицам исходного СП, включая страницы с объединёнными ячейками и продолжениями.
- Независимые примеры: цифровой PDF, скан, повреждённая кодировка, таблица без линий, смешанная ячейка с формулой и рисунком, формула вне таблицы.
- Ошибки JSON/экранирования, усечение ответа, превышение контекста, временная ошибка сети, завершение с частичным результатом.
- Тесты путей и установки на macOS/Linux/Windows; CI для всех трёх семейств ОС и отдельная проверка Ubuntu 25.
- Реальные ограниченные запросы к Ollama, затем визуальная проверка Markdown/HTML. Работа на ОС не объявляется проверенной только по тестам на Mac.

## Границы работы

Не меняется логика подготовки будущих RAG-батчей; pg-vector и базы данных не добавляются. Рефакторинг вне распознавания, проверки результатов и переносимого запуска не проводится.
